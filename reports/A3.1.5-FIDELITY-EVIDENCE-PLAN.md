# A3.1.5 controllable and textured original interactive M00

## Scope

This fidelity milestone freezes A3.1.4 as the first physically accepted visible
original interactive M00 baseline. It does not alter campaign scope, public
services, scene traversal, physics, culling, material layout, asset formats, or
performance behavior.

## Controller contract

The Vita controller reports byte axes around neutral `128`; the old platform
boundary normalized those values and multiplied by `32767`. Original Renegade
then divides the DirectInput axis by `1000`, so full right-stick deflection
entered the original action system as approximately `32.767`, rather than its
expected `1.0`.

`renegade_vita_input_contract.h` now maps the centralized device value linearly
to the existing original DirectInput logical range `-1000..+1000`, after the
same narrow device-neutral handling already at the boundary. Original Input
sliders, bindings, dead-zone processing, `CombatManager::Generate_Control`,
and original camera ownership remain unchanged. The host axis-contract selftest
covers neutral, small, quarter, half, full, and both-axis symmetry.

## Texture contract

The old Vita patch marked `TextureClass` initialized and returned a null DX8
texture. A3.1.5 restores the original ownership path:

`Mesh material -> TextureClass -> WW3D asset/factory lookup -> DDSFileClass ->`
`in-memory RGBA decode -> native Vita texture upload -> original UV draw bind`.

The source data remains in the existing retail factory/MIX chain. DDS pixels
are decoded only in memory and uploaded as RGBA; no retail file is converted,
written to the repository, or packaged in the VPK. Rows are flipped during the
platform upload to preserve the original D3D UV convention. Texture lifetime
stays with `TextureClass`; the direct Vita mesh boundary only binds its decoded
native handle.

## Candidate evidence and performance policy

The A3.1 capture subsystem is being extended rather than replaced. Candidate
exit must produce candidate-specific A3.0/A3.1 screenshots, state snapshots,
bounded frame history, input and texture summaries, performance statistics,
per-file SHA-256 manifest, and one stored ZIP under
`ux0:data/renegade/user/evidence/`. Capture/archive work is recorded separately
from measured ordinary frame timing. The archive contains telemetry only and
never retail data, arbitrary user files, or memory dumps.

Measurements describe CPU wall time and present wait; they do not claim GPU
timing. No batching, atlas, LOD, culling, streaming, texture-resolution,
physics-rate, or update-rate optimization is permitted in A3.1.5.

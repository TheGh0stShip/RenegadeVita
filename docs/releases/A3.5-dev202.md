# A3.5-dev202: Practice loading and MultiHUD

**Experimental native ARM development build.** Dev202 routes original
mode-specific loading backdrops: Practice uses state 96, remote C&C uses state
94, and campaign keeps its mission-specific backdrop. The original MultiHUD
owner is linked in the full port. The separate tutorial demo is unchanged.

## Verified

- 177 focused tests, fast ARM ELF/SELF/VPK identity, and Vita3K install/readback
  passed. This was not a canonical build.
- A bounded Vita3K run selected original Multiplayer Practice, displayed its
  original loading screen with logged backdrop 96, loaded `Skirmish00.mix`,
  rendered its world/HUD, and accepted brief movement input.
- The attached three PNGs and [35-second recording](https://github.com/TheGh0stShip/RenegadeVita/releases/download/A3.5-dev202/dev202-practice-vita3k-silent.mp4)
  match Dev202. The recording is **silent** and proves neither audio sync nor
  performance. The run was deliberately stopped after capture, not naturally
  exited.

**Not verified:** Practice bots, objectives, purchases, death/respawn,
transitions, remote C&C loading visuals, complete multiplayer, campaign, or
physical PS Vita/PSTV behavior. An earlier Dev200 Vita3K run received one live
RenCorner purchase response; Dev202 was not tested on RenCorner in this capture.

# Renegade Vita A3.1.1 Hardware Candidate

Status: packaged physical-hardware candidate; physical evidence pending.

## A3.1 crash closure

The historical A3.1 Vita crash is retained as evidence and is not overwritten.
It was `C2-12828-1`, data-abort `0x30004`, in thread `RNEGA3101`, at ELF
`0x8112E0D0` (load bias `+0xA000`).  Symbolication places the fault in
`WWAudioClass::Get_Sound_Scene()` (`WWAudio.h:439`), invoked by
`StaticAudioSaveLoadClass::Load()` (`AudioSaveLoad.cpp:138`) while the retained
A3.0 M00 static-world regression dispatches its static-audio save/load chunk.
The singleton was null, so `ldr r0, [r3, #116]` dereferenced address `0x74`.

This was an invalid startup order, not a supported no-audio state.  The original
Commando initialization constructs `WWAudioClass` before world loading.  A3.1
had instead created it only after the preliminary M00 validation.  A3.1.1 owns
one application-lifetime `WWAudioClass` around the A2/A3 validation and the
interactive session.  The Vita silent-device boundary is valid with
`Get_Sound_Scene() == NULL`; `WWAudioClass::Get_Instance() == NULL` before a
static-audio load is not.  Teardown follows the world/session teardown and
destroys that one owner exactly once.

The prior host check missed this because its seed manifest did not link
`AudioSaveLoad.cpp`, so M00 never dispatched `StaticAudioSaveLoadClass`.  The
focused two-cycle regression now begins with no singleton, constructs the
application owner, requires the static-audio load breadcrumb, confirms the
silent sound-scene boundary, and confirms null singleton state after teardown.

## Additional causal compatibility repair

The post-audio interactive host path exposed the original UTF-16 packet writer
selecting `Add(int)` for distinct GCC `WCHAR`, whereas VC6 selected its 16-bit
overload.  The narrow `BitStreamClass` patch explicitly serializes each WCHAR
as `USHORT`, matching the existing 16-bit reader.  This preserves original
WWNet/cNetwork serialization and repairs the original local server’s player
name acceptance; it does not replace replication.  GameSpy/public discovery
remain inactive behind the existing provider boundary; LAN and direct-IP
interfaces remain the baseline.

# A2.0 Physical Hardware Validation

Status: **ACCEPTED — PASS**

Validation date reported by the hardware tester: 2026-08-07.

## Purpose

A2.0 established the first known-good native PS Vita foundation for the
official EA/Westwood Command & Conquer: Renegade source. It proved that genuine
original code compiles for ARM with VitaSDK, executes on physical Vita
hardware, can inspect the unchanged permanent retail tree, can create and use
the separate writable tree, can display native diagnostics, and exits cleanly.

## Architecture used

- Native PS Vita ARM executable and VPK built with VitaSDK.
- Official EA CnC_Renegade source at pinned revision
  3e00c3a1b97381bb28be89a35b856375e0629a08.
- Original source compiled into a distinct westwood_original static library.
- Centralized MSVC/Win32 scalar compatibility for the ILP32 Vita ABI.
- Explicit staged portability patch; canonical upstream remained pristine.
- VitaSDK native framebuffer/debug-screen helper, not vitaGL.
- Thin Vita filesystem/controller/process boundary.
- Original retail data read unchanged from
  ux0:data/renegade/retail/Data/.
- Writable state isolated under ux0:data/renegade/user/.

## Compatibility work

The A2.0 compatibility headers provide old MSVC spelling compatibility,
Win32/Vita ILP32 scalar types with width assertions, explicit 16-bit WCHAR
semantics, and the narrow miscutil dependency required by mathutil.

port/patches/wwbitpack-gcc15.patch applies only to staged copies:

- two rejected VC6 functional casts became equivalent static_cast expressions;
- a VC6 loop-variable scope dependency was made standard C++;
- a redundant in-class constructor qualification was removed;
- unsafe short-object reinterpret-cast loads/stores in bitstream serialization
  became size-bounded memcpy operations with a zero-initialized ULONG.

The algorithms and serialized little-endian behavior were preserved.

## Acceptance criteria

All A2.0 host, packaging, filesystem, original-code execution, framebuffer,
runtime logging, controller-exit, and crash-free physical-hardware criteria
passed. A2.0 is the known-good regression baseline for all later milestones.

## Deliberately not implemented in A2.0

- Original wwlib file implementation and file factories.
- Original archive/MIX access.
- wwsaveload, wwtranslatedb, wwphys, ww3d2, Combat, or Commando runtime.
- DirectX/vitaGL/SceGxm renderer integration.
- Input beyond START exit.
- Audio, Bink, Umbra, networking, WOL, or GameSpy.
- Campaign or multiplayer world loading.
- Any custom runtime archive parser or converted asset format.

## Constraints and lessons for later milestones

- Preserve every validated A2.0 behavior as a regression check.
- Physical Vita is the authority; arm-vita-eabi-run is not a hardware
  simulator.
- Host tests must preserve Win32/Vita ILP32 widths instead of silently using
  Linux LP64 ULONG semantics.
- Keep retail immutable and route writable state separately.
- Keep upstream pristine and apply explicit patches only to deterministic
  staging copies with zero fuzz.
- Extend original Westwood abstractions by replacing platform boundaries; do
  not replace engine systems.

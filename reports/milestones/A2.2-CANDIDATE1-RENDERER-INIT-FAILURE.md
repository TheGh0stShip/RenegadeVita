## Renderer failure and exact cause

The application reported renderer initialization failure and therefore never
entered original SimpleScene/Camera traversal. Frames, meshes, vertices,
triangles, unsupported submissions, and geometry checksum were all zero.

The backend treated `vglInit(4 MiB) == GL_FALSE` as failure. The installed
`libvitaGL.a` embeds revision `6e7fe40`; its matching source sets the internal
initialized flag and returns `res_fallback`. That result is not a success flag:
it is zero at the normal requested 960x544 resolution and one only if the
resolution was clamped. Official examples ignore it. Final candidate ELF
disassembly confirmed that the application branched to its failure return when
the normal zero value was received.

The vitaGL splash runs asynchronously. It is stopped by the first
`scene_reset`, reached through an operation such as `glClear` or a draw. A
buffer swap is deliberately ignored while the splash is active. The false
failure branch returned before the first clear, so the logo continued spinning
even though vitaGL initialization had returned.

Exact audited graphics identities:

- vitaGL revision: `6e7fe40292e8f1d10f9a94ff2cd2f4fb1ba452a5`.
- Installed `libvitaGL.a` SHA-256:
  `bcc414e745a1f29940f7c33418f268c4cd78d0388b7a0da0f036b72355597b69`.
- Installed archive was built with `NO_DEBUG=1`/`SKIP_ERROR_HANDLING`; most
  private SceGxm return codes are discarded, so `glGetError` cannot prove each
  internal stage.
- vitaShaRK default compiler module path: `ur0:/data/libshacccg.suprx`.
- vitaGL fallback compiler module path: `ur0:data/external/libshacccg.suprx`.
- START-observed status was FAIL only because the scene/input loop was
  unreachable after the false return. The visible splash proves the graphics
  path was entered, but does not by itself prove shader compiler success.

Detailed source/API/binary evidence is retained in
`reports/A22_RENDERER_DIAGNOSTICS.md`, `reports/A22_VITAGL_API_AUDIT.md`, and
`reports/A22_VITAGL_INIT_ANALYSIS.md`.

## Corrective constraint

Interpret the `vglInit` result only as `resolution_fallback`, never as
initialization success. Persist flushed breadcrumbs around initialization,
shader availability, memory/configuration, first clear, first present, and the
first original mesh submission. Continue through the unchanged original
SimpleScene/Camera/WW3D path. Do not create a replacement renderer or manually
extract the validated mesh geometry.
